# A2P3 - An Uncertainty-Aware Collaborative Inference Architecture for Privacy-Preserving On-Device Foundation Models

**Track:** Track 7  
**Application:** Smart-city traffic camera analytics across device edge and cloud

This dataset is synthetic, generated by gen_author2.py with seed 2049. It must be described as synthetic in any publication.

## Simulated scenario

400 smart-city traffic cameras run a compact vision model on-device and can split inference to edge nodes or the cloud. Frames vary in weather, lighting, density and occlusion; tasks include vehicle counting, plate blurring, incident detection and pedestrian safety. Each frame logs device-side uncertainty signals, network/edge state, the chosen partition, and outcomes.

## How it was generated

Latent difficulty = weather + night + 1.4 occlusion + density + noise; device entropy/variance/confidence are noisy functions of difficulty. Error risk r = 2.6 difficulty - 0.35 capacity - 1.1 capacity x [difficulty>0.6], standardised to z; P(error) = sigmoid(-3 + 4 z), so offloading pays off mainly on hard (high-uncertainty) frames. Latency = compute + payload/bandwidth + edge queueing (load) or cloud RTT; energy and privacy exposure depend on partition. Partition logged at random (uniform-ish) to enable counterfactual routing studies. 5% noise, 1-3% missing in 3 columns, ~0.7% outliers in 2 columns.

## Target / label column(s)

`prediction_error` (binary, ~25% errors). Outcomes `latency_ms`, `device_energy_j`, `privacy_exposure` for multi-objective routing.

## Suggested experiments

1. Error prediction from uncertainty + context: does device_pred_entropy predict failure? AUROC, F1.
2. Uncertainty-aware routing: offload only when predicted device error > tau; plot accuracy vs mean latency and energy vs fixed device-only / always-edge / always-cloud baselines.
3. Privacy-constrained routing: forbid cloud_full when privacy_sensitivity >= 1; report accuracy loss.
4. Robustness: train on clear weather, test on fog/snow/night frames.
